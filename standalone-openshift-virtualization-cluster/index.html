    Networking & services

    Choose how cluster VMs connect. Additional network and service settings appear based on your selection.

    Pod networking or bridge networking

    Pod networking uses an API Route and the infrastructure cluster’s DNS for ingress, without VIPs or new DNS records. Bridge networking lets clients reach the cluster API and ingress through dedicated IP addresses on a bridged network, rather than through the infrastructure cluster’s pod network. Choose the mode that fits your network requirements.

    Customize networking and services

    Bridge networking (VIPs)

    Requires API VIP, Ingress VIP, and machine network CIDR.

    Select a pre-existing bridge network or localnet for cluster VMs. CUDN is not supported in Tech Preview.

    Create a DNS A record for the cluster API pointing to this VIP before installation.

    Create a wildcard DNS A record for cluster ingress pointing to this VIP before installation.

    In bridge mode, create both DNS A records before installation. DNS resolution is checked after the VMs boot; the UI cannot verify it before creation.

    OVN settings

    Suggested from the selected infrastructure cluster and adjusted for OVN encapsulation.

    Geneve port

    Must differ from the infrastructure cluster default (usually 6081) so the new cluster and infrastructure cluster OVN overlays do not collide.

    Suggested to avoid the infrastructure cluster’s Geneve port.

    Cluster services

    Required infrastructure integration is configured automatically. Persistent storage remains optional.

    Cloud controller manager (CCM)

    LoadBalancer services are available through the infrastructure cluster. Recommended for pod networking.

    Container storage interface (CSI) driver

    Lets workloads in the new cluster create persistent volumes using storage from the infrastructure cluster.

    Infrastructure storage class for CSI

    Storage class on the infrastructure cluster used by the KubeVirt CSI driver to provision volumes for the new cluster.

    The recommended class is selected automatically. It provisions volumes for the new cluster on the infrastructure cluster.
