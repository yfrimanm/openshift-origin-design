Memory request ratio — UX documentation

Goal

Replace Memory density with a memory request ratio control: requested memory as a percentage of configured memory, on a 0–100% range.

  • Set the cluster-wide default ratio with a PF6 number input (no slider)
  • Save when the value changes
  • Restore default to reset the field to 97.5%
  • Full context in the ? help popover only

Related bug: CNV-88963. KSM unchanged in this mockup.

UX summary

Current problem (today)

The current Memory density control uses a percentage slider that can go above 100%. It does not explain configured vs requested memory, so values like 120% are hard to interpret without backend context. Bounding the UI at 0–100% ties the control to one relationship admins can reason about: requested ÷ configured.

Terminology

We are replacing the existing Memory density with Memory request ratio. The memory request ratio is the percentage of each VM's configured memory (the VM's memory size) that is requested on the cluster, on a 0–100% range. This setting sets the cluster-wide default ratio for all VMs.

Control

PF6 Number input with unit for Saved ratio. Two values inside the accordion:

  • Applied ratio — read-only live cluster value (e.g. 94.2%)
  • Saved ratio — editable cluster default with Save / Restore default

Applied ratio

Applied ratio: 94.2% with ? — read-only. The actual real-time memory ratio currently calculated across all VMs on the cluster. This fluctuates based on active system load and resource availability.

Saved ratio

Saved ratio label with ? above the number input. The cluster-wide default the admin sets. ? popover — after changes are saved, they apply cluster-wide:

  • New VMs: Use the saved ratio immediately, unless they have a specific ratio set by the VM owner.
  • Running VMs: Retain their current ratio until they reboot or migrate.

Validation

If the value is outside 0–100, we show: Enter a value from 0 to 100.

Ratio levels (traffic light)

A lower ratio requests less memory on the cluster and increases overcommit risk.

When the value is valid, show a colored dot and short label below the number input. This is informational only and does not block Save.

Level definitions are in the ? help popover.

LevelRangeLabelMeaning
Green75% – 100%RecommendedRequests most of configured memory. Default 97.5% is here.
Yellow50% – 74.9%Use with cautionModerate overcommit; monitor memory pressure.
RedBelow 50%High overcommit riskEach VM requests less than half of configured memory.

Thresholds are proposed for the mockup — confirm with engineering and PM.

Save

We show Save (secondary button) only when the entered value differs from the saved cluster setting. No Cancel button.

Restore default

When the value has been edited, Restore default (link button) appears to the right of Save. It resets the field to 97.5% without saving. If 97.5% matches the saved setting, the action row is hidden again.

Interaction

  • Default — mockup loads at 97.5%
  • Edit — type or use − / + (0.1% steps, 0–100)
  • Save — when Saved ratio differs from last saved setting
  • Rollout — running VMs apply the saved ratio after reboot or migrate
  • Restore default — link button with Save; resets to 97.5%
